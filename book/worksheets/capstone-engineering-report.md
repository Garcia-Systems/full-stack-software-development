# Capstone engineering report

## Business requirement
What user/business problem was solved, and what observable outcome defines success?

## Assumptions
List ambiguities resolved with the product owner. Separate facts from assumptions.

## Architecture
Include the proposed Mermaid diagram, changed boundaries, ownership decisions, and why unchanged layers stay unchanged.

## Data model
Describe persistent structures, relationships, constraints, indexes, lifecycle, and migration compatibility.

## API contract
For every capability record method, route, input, success representation, important failures, and authorization.

## Security
Explain identity, authorization, tenant isolation, token generation/storage/exposure, expiry, replay resistance, rate limits, and safe logs.

## Reliability
Name the transaction boundary and explain duplicate requests, concurrent acceptance, expiration, revocation, and failed notification delivery.

## Testing
Link each important business risk to automated evidence and record exact commands/results.

## Deployment
Record artifact version, migration order, configuration changes, deployment command, and post-deployment evidence.

## Observability
List safe correlation identifiers, events, logs, delivery state, and the investigation path for a reported access failure.

## Tradeoffs
What was deliberately deferred? What would change with more time or scale?
